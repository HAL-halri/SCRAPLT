# SCRAPLT（ゴミ集め船旅）

## ゲーム概要

プレイヤーは船で海を航海しながら、漂流するゴミを収集していく放置型のゲームです。
集めたゴミは港で売却でき、Goldを使って船の性能を強化し、より深い海域（Stage）へと旅を続けられます。

汚染された海を舞台に、「ゴミを集める」というモチーフで、環境問題のメッセージも込めた作品です。

## ゲームの遊び方

### 基本サイクル
1. **タイトル画面でタップ** → 本編スタート
2. **「航海に出る」ボタンで出航** → ゴミが自動で集まる
3. **燃料・倉庫の状況を見て帰港** → アイテム売却でGold獲得
4. **強化で性能アップ** → より効率的に航海
5. **Stage進行で新しい海域へ**

### 画面構成

- **ヘッダー**：船名、Rank、Gold、Fuel残量を表示
- **メイン画面**：
  - 停泊中：港町桟橋の背景、航海状態の表示
  - 航海中：海の背景、燃料切れ・倉庫満タンまでの残り時間を表示
- **Footer**（4ボタン）：
  - 港/船室：補給、商人（交易）
  - 強化：Storage/Fuel/Speed/Bonusの4軸強化
  - 倉庫：所持アイテム確認、売却、キープ数設定
  - 設定：船名変更、音量調整

### 主要機能詳細

**強化システム（4軸）**
- Storage（倉庫）：満タンまでの時間拡張、素材=木の板
- Fuel（燃料）：航海可能時間拡張、素材=汚れたオイル
- Speed（航海速度）：アイテム収集間隔短縮、素材=スクラップ
- Bonus（運搬効率）：ボーナスGold獲得量アップ、素材=布
- Lv11以降はGoldに加えて素材要求

**交易システム（商人）**
- 強化素材4種をGoldで購入可能
- 購入制限：各素材1日30個まで（0:00リセット）
- 購入価格：売却価格の1.5倍（緊急用途）

**セーブ機能**
- 30秒ごとの自動セーブ
- アプリ終了・一時停止時にも即保存
- 次回起動時に状態復元

## 主要機能

- **放置ゲーム**：自動でアイテム収集が進行
- **航海/停泊の切り替え**：プレイヤーの能動的な操作
- **4軸の強化システム**：Gold + 素材要求
- **ステージ進行**：3つのStageを順次解放
- **交易機能**：緊急時用のアイテム購入
- **タイトル画面**：フェード演出、BGM、SE
- **サウンド**：BGM、環境音ループ、効果音
- **視覚演出**：ボーナスGold獲得時のコイン弾けアニメーション
- **UI/UX**：ピクセルアート調で統一されたデザイン

## 制作環境・技術スタック

- **ゲームエンジン**：Unity 2022.3.62f3
- **言語**：C#
- **ビルドターゲット**：WebGL（ブラウザで動作）
- **解像度**：1080x1920（モバイル縦画面想定）
- **PC対応**：縦画面比率を保つカスタムWebGLテンプレートで中央寄せレターボックス表示

### 主要な実装

- **データ管理**：ScriptableObject（ItemData、ShipStageData、DropRateData）
- **UI管理**：PanelManagerによる排他制御
- **セーブ**：PlayerPrefs + JsonUtilityでJSONシリアライズ
- **サウンド**：BGMManager（Singleton）、フェードイン/アウト対応
- **演出**：FadeManager（Singleton）による汎用フェード、FlyingObjectSystemによるコイン弾けアニメーション

## こだわった点

### 1. ピクセルアート調で統一された世界観
UIからキャラクター、背景まで一貫したアートスタイルで、「海の冒険」の雰囲気を表現しました。

### 2. 没入感のあるサウンド設計
- タイトル画面：壮大な8bit系BGM
- 停泊中：穏やかな環境音
- 航海中：波の音 + 船の軋み
- 状態変化時のフェード切替で滑らかな遷移

### 3. 放置ゲームとしての戦略性
- 燃料・倉庫の制約があり、適切なタイミングでの帰港判断が必要
- 強化の優先順位の選択
- 素材の売却/強化/交易の使い分け

### 4. UX配慮
- 出航/帰港時の確認ダイアログで、予想航海時間などを事前確認可能
- 購入制限リセットまでの残り時間表示
- Gold不足・素材不足時の視覚的フィードバック（赤文字表示）
- 音量調整機能

### 5. アーキテクチャ
- Singletonパターンで一元管理（GameManager、BGMManager、FadeManager）
- イベント駆動（OnGoldChanged、OnSailingChangedなど）でUI更新
- SaveData / SaveSystem分離で保存ロジックの再利用性確保
